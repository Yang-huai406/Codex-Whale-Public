# Codex-v0.4(fixixed)：开发历程与产品能力

本文整理项目开发讨论形成的决定、累计功能和本次修复，不复制原始聊天、私人配置、真实服务地址、凭据、账本或测试现场。

**本版发行说明。** 对外名称精确为 `Codex-v0.4(fixixed)`，发行标签为 `codex-v0.4.0(fixixed)`；内部版本 `0.4.1`，构建标识 `surface-audio-fix-20261007`。`fixixed` 是本次约定拼写，不能用旧名称 `fixed` 替代。

当前公开项目为 [Yang-huai406/Codex-Whale-Public](https://github.com/Yang-huai406/Codex-Whale-Public)，本次发行的目标分支为 `main`。[Yang-huai406](https://github.com/Yang-huai406) 是该独立仓库所有者和维护者；下文 For-Codex 指迁移前的适配历史，不是本次上传目标。

## 产品定位与累计功能

小鲸鱼从 DeepSeek 余额挂件发展为独立的 Codex 桌面伴随工具，保留角色、气泡、音效与交互，并按可验证的数据来源展示余额、已观测消费和用量。兼容推理 API 不代表兼容余额 API；没有可靠余额数据时明确保留未确认或不查询状态。

| 能力 | 当前产品行为 |
| --- | --- |
| 桌面角色 | 跟随 Codex 或作为独立桌面浮窗；拖动、缩放、翻转、位置记忆、气泡和音效；透明空白区域仍允许操作底层应用 |
| 操作界面 | 概览、用量和设置；本地素材工坊、角色/音效管理、预算与预警、图表和匿名历史账户入口 |
| API 连接 | 跟随实际读取的 provider/profile/project 配置，或固定选择命名连接；支持独立余额地址、GET/POST JSON、专用认证和受限环境变量引用 |
| 自动检测 | 有界尝试有来源依据的协议和路径，校验契约及单位；可信命中直接使用，完整候选可核对后采用 |
| 金额与任务 | 账户新增消费、任务状态、本轮 token、按模型价格估算的费用分别展示；内部保留精度，界面按显示规则呈现 |
| 订阅与历史 | 独立处理五小时/每周额度快照；旧匿名账户历史可查看，不要求旧密钥仍有效 |
| 安装和恢复 | 安装预检、插件注册与实际构建核对、私有回执和回滚；恢复程序不删除最新账本、设置与素材 |

窗口的“跟随 Codex”与余额连接的“跟随配置”是不同设置，分别决定挂件显示位置和查询来源。使用说明见 [README](../README.md)。

## 早期：独立窗口与交互基础

初始适配目标是在 Codex 中保留原挂件的外观和交互，同时读取 API 余额。实现逐步形成独立 Electron 透明工具窗口、Windows 原生跟随、GUI 启动器、受限本地 IPC、安装备份和回滚流程，不向 Codex 主页面或输入框注入 DSH 的 DOM 逻辑。

随后完善本地工坊、设置、预算、图表、账户历史和订阅显示。“挂件消失”被拆成窗口隐藏、合成、绘制区域生命周期与窗口层级等不同问题分别处理。位置记忆保存用户位置意图，避免启动动画、临时缩窗或无关设置保存覆盖它；拖动取消、失焦和捕获丢失不提交无效坐标。

连续点击推动人物命中轮廓、输入路由和原生窗口区域保持一致，减少角色缩放回弹时点到背后控件的问题。气泡队列、图片回退、截止时间与旧异步回调统一生命周期，长文和图文使用通用安全区布局。

全局空白点击关闭曾经试作，随后主动撤回。底层软件的正常点击不能一概视为用户已经读完提示，因此采用明确关闭、人物交互和提示自身超时；#177 是设计决定，见 [空白点击说明](OUTSIDE-CLICK-DECISION.md)。

## v0.4：计量边界与 Issue 核查

并行任务暴露了账户差额的归属问题：同一个 key 的区间扣费可能来自其他聊天、设备或延迟入账，不能全归给某一轮。后续将账户新增消费、每轮状态与 token、按模型价格估算的费用分开。首次有效样本建立基准，后续新增批次持久化并去重；暂停展示时合并累计，恢复后展示。

账本保留原币种，汇率只影响显示。内部精度与两位小数展示分离，极小增量不会仅因显示舍入而被丢掉。关闭挂件只停止观察，不停止 Codex 请求；失败或取消仍可能收费，本机会话 token 也不等于官方订阅余额。

Issue 核查先比较原讨论与 Codex 实际路径，不把 DSH 的标题或上游评论直接当作本分支能力。累计修复涵盖额度来源与逐窗口合并、气泡队列与排版、严格配置读写、初始化竞争、旧账户入口、名称往返、音频裁剪生命周期及隐藏后的过期提示。

范围始终保留：#108 不含共享台词池，#79 不含完整 Android 触控实现，#135 不等于 Mac 睡眠实测，#184 不等于精确历史流水。输入框避让、等待授权/阶段事件、点击跳转聊天、独立透明度和通用额度回退等仍未完成。现状见 [本次 Issue 表](ISSUE-STATUS-FIXIXED.md)。

## 初期 0.4.1：先隔离连接与认证

多 provider、自定义中转与独立账单域名的反馈推动了命名余额连接。配置表递归合并；未知 provider 明确失败；地址、租户路径、认证头和环境引用绑定来源，防止切换服务后旧地址与密钥覆盖漂移。跟随模式只反映实际读取到的配置，固定连接也不保证等于当前聊天采用的推理服务。

高级请求增加完整/相对 URL、GET/POST JSON、同源继承或专用认证、结构化头与参数。秘密通过受支持的环境变量引用取得，不直接保存到普通设置。预览不落账，正式口径变化先建立新的计量基准，#190 因此为部分覆盖，不能再按旧版描述为“只支持 GET”。

这一阶段的自动模式过于保守：即使第三方返回可识别字段，也常停留在未确认，普通界面又缺少直接采用候选的入口。相关历史见 [初期连接模块说明](PROVIDER-CONNECTIONS-0.4.1.md)，其中旧自动规则和测试数字不是当前规则。

## fixed：有依据的自动识别与直接确认

后续依据公开源码、官方文档和 SDK 核对协议范围、字段与单位，实现有界顺序探测。关键区别包括：兼容账单的 `100000000` 可能是不限额哨兵；NewAPI 原生 `total_*` 是整数 quota；`credit_summary.total_used=0` 是占位值；相同账单形状可能表示账户或 key；管理 credits 与普通推理 key 额度不是同一接口。

最终流程为：尝试已知同源路径和别名，校验完整契约；可信命中直接使用；有完整可核对规则的候选提供“确认并使用”；仍缺少依据时保留未确认和高级配置。注册表的十三项包含别名、双请求账单、匿名单位元数据及管理接口条件，不是十三个品牌逐一实测，也不是每次全部请求。

原始 quota 先验证安全整数与加总关系，再按可靠单位或确认规则换算。不限额不显示成巨额有限资金，占位消费不参与差分；协议、字段、单位、范围或计数器周期变化时更换计量基准，避免将不同指标相减。

缓存保存识别计划和单位元数据，明确未命中短暂缓存；预览与实时查询共享限流退避。候选采用使用绑定草稿、配置与来源的限时单次证明，防止旧窗口或迟到结果误保存。普通用户可完成检测、核对和采用，不必先填写 JSON。见 [自动检测说明](AUTO-PROBE-FIXED.md) 与 [协议公开来源](BALANCE-PROTOCOL-SOURCES.md)。

## fixixed：显示失效保护与连点声音

Windows 用户反馈原版 0.4.0 出现白屏遮挡。核查发现，原版与 fixed 的正式窗口路径已有默认软件合成、透明背景和区域裁剪，但只相信设置调用及缓存，没有持续验证实际原生区域。录屏确认了现象，未唯一定位设备上的触发根因；本次修复的是已确认的保护缺口。

新增常驻原生监控，核对完整区域并集及窗口/进程身份，用实例、尺寸代次和形状序号绑定验证。区域丢失、持续无法验证、监控失联或渲染异常时撤销显示；旧成功回执不能重新打开失效窗口。正常动画保留已验证显示，隐藏期间合并更新，避免确认饥饿及恢复闪烁。连续未验证期限独立于不断变化的动画序号，恢复次数有上限，持续健康后才重新开放预算。

监控使用异步隐藏，避免同步等待目标窗口；渲染无响应时重新加载并重新验证。没有自动结束 Codex 或其它应用进程。合法区域内部没有故障事件的合成异常、Electron 主线程永久卡死等仍有边界，因此 #121 继续列为部分覆盖。

另一项反馈是小黄鸭快速点击听感破碎。按下和松开原先共用交互通道并直接停止播放，容易在非零波形上硬切并反复重启音节。现在采用 8ms 短交叉淡变，合并 90ms 内过密声音及配对松开，丢弃过晚的交互声；取消、隐藏、静音后清理尾音，旧解码不能复活。实际点击和动画不被限制，声音不排队补播；任务整组声音与设置试听仍用独立通道。这与 #187、#197 尚未明确复现的设备/双声问题不是同一根因。

安装检查也进一步核对已启用的插件注册和实际运行构建，避免“代码复制成功”被误报为“新版正在运行”。多个构建内部版本都为 0.4.1，必须同时核对 build。专项机制、测试方法与回滚说明见 [白屏与连点音效](SURFACE-AUDIO-FIX-20261007.md)。
