# Codex-v0.4(fixixed)：已知限制与待验证事项

**本版发行说明。** 适用名称 `Codex-v0.4(fixixed)`，发行标签 `codex-v0.4.0(fixixed)`；内部版本 `0.4.1`、构建 `surface-audio-fix-20261007`。`fixixed` 是本次约定拼写。本文不把一次本机通过、历史基线或隔离故障注入当作全部设备验收。

当前项目为 [Yang-huai406/Codex-Whale-Public](https://github.com/Yang-huai406/Codex-Whale-Public)，本次发行面向 `main` 分支。公开迁移已于 2026-10-05 完成，已有 fixed 发行已迁移；历史上游 Issue 仍保留原讨论地址。本次待验状态只指新的 `fixixed` 候选，不代表新公开仓库尚不存在。

## Windows 白屏保护与恢复

| 项目 | 当前边界与用户预期 |
| --- | --- |
| 原反馈根因 | 录屏能确认白屏遮挡现象，代码审计证实区域保护缺口；两者不能证明用户设备上的唯一触发根因已复现。#121 仍为部分覆盖 |
| 正常保护状态 | 正常显示后 `rendererReady` 与 `surfaceGuard.verified` 应为 true，`failure` 应为 `null`；尺寸变化和恢复时可短暂重新验证，不应持续闪现或不断增加撤销计数 |
| 合成异常 | 实际原生区域正确，但合法区域内部出现白色合成异常且没有故障事件时，不能仅靠几何验证识别像素颜色是否错误；不能承诺全部显卡/驱动白屏根治 |
| 主线程完全卡死 | 异步隐藏避免监督器同步等待目标线程，但不保证目标主线程永久卡死时立即完成隐藏。渲染进程挂起与主线程卡死是不同情况；当前没有自动结束 Codex 或其它应用进程 |
| 恢复上限 | 先撤销显示，再做有界恢复；旧验证不能打开失效窗口，持续健康后才重新开放预算。长时间隐藏应查看状态并尝试一次托盘恢复，不应通过禁用保护强行显示 |
| 调度时间 | 25ms 原生采样、100ms 稳定判断、1000ms 连续未验证期限及心跳检查是调度参数，不是高负载下的硬实时承诺 |
| DPI 与显示环境 | 本次完成 150% DPI 下 8 组 Windows 原生场景；不代表所有缩放、多屏跨屏、驱动、远程桌面和长期高负载环境均已通过 |
| 本机短期观察 | 记录中出现过 1 次保护撤销并恢复，但没有该次具体故障原因；不推断为原白屏、GPU 故障或某条确定分支，也不写成“零保护事件” |

仍白屏时，可从托盘隐藏/退出挂件，观察底层是否恢复，再记录构建、系统、DPI、触发操作及必要的 `surfaceGuard` 字段。隐藏后白块仍存在时，需要区分宿主自身重绘问题。详细机制和操作见 [专项说明](SURFACE-AUDIO-FIX-20261007.md)；不要用破坏日常窗口的方式自行注入测试故障。

## 连点音效与设备听感

| 项目 | 当前边界与用户预期 |
| --- | --- |
| 超密点击 | 合并的是过密声音请求及其配对松开，实际点击和动画继续处理；不保证极密点击每次都发声，也不会松手后排队补叫 |
| 单击和长按 | 仍使用原素材，交替声音采用短交叉淡变；长自定义声音松开时及时淡出，不应留下无法停止的尾音 |
| 迟到与取消 | 超过 250ms 才准备好的交互声丢弃；取消、隐藏或静音后旧解码不能复活。网络或解码迟缓时偶尔不发声不等于点击失效 |
| 数字验证范围 | 真实小黄鸭素材在 OfflineAudioContext 中完成 8 个离线场景，检查调度、音源数量与数字削波；没有实际播放扬声器声音，不替代真实耳机/扬声器听感 |
| 设备首音问题 | #187 的原故障设备仍待实测，未增加专用前导唤醒方案。本次减少硬切不等于修复设备休眠唤醒吞首音 |
| 双重声音 | #197 原根因尚未在当前版明确复现；保留单实例、去重及通道管理，但不能把连点合并当作同因修复 |
| 睡眠和平台 | 音频生命周期及尾音清理不等于 #135 的 Mac 睡眠断言已经通过；不同系统和音频驱动仍需实际验收 |

建议分别试听慢点、连点、长按松开、静音、自定义音组、任务提示和设置试听。预期硬切与破碎减少；最终听感由用户确认，不用离线波形数字代替主观结论。

## 余额接口与配置

| 项目 | 当前边界 |
| --- | --- |
| 自动识别范围 | 有来源依据的若干协议族、路径别名和元数据；13 项注册记录不是十三个品牌分别实测，也不是每次全部请求 |
| 未知单位或范围 | 强契约才自动生效；完整候选须对照服务商账单核对。无法形成可靠规则时需要高级配置或选择不查询，不能把未知当零或现金 |
| 兼容推理协议 | OpenAI-compatible 只说明推理接口兼容，不意味着存在标准余额接口或普通推理 key 有账单权限 |
| 管理接口 | 普通推理 key 不默认试探管理接口；账户 credits 等可能需要专用认证。某余额端点拒绝 key，不足以证明该 key 无法调用模型 |
| 兼容账单 | 相同形状可能表示账户或 key 额度，字段名 `*_usd` 也不总能独立证明实际币种；不能称所有兼容账单已自动确认 |
| 原始 quota | `token_usage` / `credit_summary` 的 `total_*` 不是天然货币；使用可靠元数据或确认规则换算，避免重复除默认单位 |
| 复杂认证 | 支持 GET/POST JSON、受限头/参数与环境引用；任意网页登录、表达式执行和将秘密直接持久化到 body 等未提供。#190 为部分覆盖 |
| 配置来源 | 跟随实际读取的 provider/profile/project 配置，不包括未读取的 CLI 临时覆盖；固定连接也不保证就是当前聊天的推理服务 |
| 秘密与运行环境 | 密钥环境变量必须在运行挂件的进程中可用；程序不替用户创建凭据或修复服务商权限，普通预览不返回秘密 |
| 迁移和回滚 | 旧地址和密钥覆盖须绑定来源；回滚旧程序后可能重新采用旧根设置，应核对实际连接及金额口径 |
| 限流和缓存 | 单次请求、整轮时间和数量都有上限；超时/限流可能使探测未找到可用接口。手动重新检测不能绕过限流退避 |
| 服务端变更 | 路径、响应、范围或单位改变后可能需重新确认；不跟随任意重定向转发认证，也不能替服务商提供缺失的余额 API |

本次显示/音效修复没有重新实测所有真实提供商。协议依据见 [公开来源表](BALANCE-PROTOCOL-SOURCES.md)，自动检测和候选采用见 [接口说明](AUTO-PROBE-FIXED.md)，操作入口见 [README](../README.md)。

## 金额、历史、订阅与通知

| 项目 | 当前边界 |
| --- | --- |
| 账户新增不是单轮账单 | 差额可能含并行聊天、其他设备及延迟入账；不能全归给一个对话。按模型价格计算的本轮估算是另一项指标 |
| 首次与新基准 | 首次有效样本、账户或计量口径变化先建立基准，不追报此前消费；暂时没有新增气泡不代表过去免费 |
| 显示精度 | 内部保留详细金额，界面按规则显示；两位小数不等于内部只有两位精度，也不能用显示差额代替原始账本差额 |
| 旧历史 | 不自动校正旧错误口径、回填旧账单或恢复已删除记录；不同原币种和匿名账户不擅自合并 |
| 退款净额 | 目前只累加正向消费差额；余额回升或累计用量回退不冲减旧累计，统计可能高于退款后的净支出 |
| 同时充值与消费 | 只有余额快照时只能看到净变化，无法拆解每笔充值、退款和消费 |
| 中断与跨日 | 恢复时处理差额，但不能精确分配中断期间每天的支出，没有完整流水导入或人工补录；#184 未全面完成 |
| 更新延迟 | 定时、任务事件和手动刷新会触发采样，仍受入账速度和退避影响；不保证每轮结束立刻显示金额 |
| 暂停与去重 | 暂停提示、隐藏或切到订阅模式时可能合并 API 待展示增量；恢复的一笔合并金额不等于刚刚一次请求花费。存储损坏/删除和崩溃组合下不承诺绝对一次展示 |
| 失败与取消 | 已发出的请求仍可能收费；零 token 记录不能独立证明免费，未知金额不能补成零 |
| 订阅快照 | 五小时和每周额度依赖会话提供的数据，可能缺失、过期或受扫描上限影响；本机 token 不等于官方固定剩余额度 |
| 汇率 | 汇率仅供显示参考，不修改账本原币种；服务商价格及有效期仍须核对 |

## 安装、回滚、证据与反馈

普通安装需要 Node.js 24+、npm、可用的 Codex 插件注册入口及首次下载 Electron 的网络。ZIP 不是完整离线 EXE；权限、网络或注册失败须按实际错误处理，不能把文件复制成功称为新版已经运行。Python/Pillow 等是开发 QA 依赖，不是普通用户安装所必需。

前后内部版本可能都为 `0.4.1`，请同时核对 build 和自己的本次安装回执。回滚先使用对应回执做 `-CheckOnly` 检查，再按 [README](../README.md) 使用同一回执恢复程序与启动配置，保留最新设置、素材和账本；不凭版本号猜备份，不用删除账本代替回滚。Mac 使用 [macOS 对应流程](MACOS.md)。

本次执行过 510 项全量自动测试；最后安装检查改动后另通过 15 项针对测试，其中 3 项新增，不能写成 513 项全量重新执行。Windows 实机为 150% DPI 下 8 组原生场景，真实小黄鸭素材为 8 个离线场景。此前 fixed 的 482 项、9 项隐私门禁、6 组流程/7 个布局样本/8 张截图，以及更早的 341 项、120 次连击、18 次透明对照和 52 个布局场景都保留为各自历史证据，不相加、不冒充本次重跑。成品检查以本次随包报告为准。

反馈请提供公开版本/build、系统与显示/音频设备环境、操作步骤、预期和实际结果。金额问题注明账户新增、累计、key 额度还是单轮估算；保护问题提供必要状态字段。不要上传密钥、完整 provider 配置、个人路径、原始聊天、账本、私有回执或未脱敏截图录屏。
