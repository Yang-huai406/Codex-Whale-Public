# macOS 点击卡片外与切屏返回后失去响应修复

日期：2026-10-12。状态：已安装本地修复，用户手动确认两条复现路径均恢复正常；未发布新版本。

## 已确认的原因

设置卡片打开后点击透明区域，点击穿透给底层应用。旧版在 macOS 开启忽略窗口的鼠标移动转发；页面可能看到按键仍按住的移动事件，却收不到底层应用接收的松开事件。输入层因此保留 `externalDrag=true`。Mac 的光标消息此前没有有效的原生按键采样时间，无法用真实的松开状态清除该标记。

用户保留故障现场时，连续 80 次只读采样均显示：

- 原生窗口在当前 Space，正常显示、未被遮挡，且位于宿主之上。
- 页面已经命中卡片：`hit=true`，没有捕获中的指针：`held=false`。
- `externalDrag=true`，`inputEnabled=false`，原生 `overlayIgnoresMouse=true`。
- 位置和大小稳定，恢复计数没有增长。

因此，无法点击的直接原因是过期的外部拖动状态持续要求点击穿透。切屏、切换跟随/桌面模式会取消交互状态，所以暂时恢复。先前仅修改层叠与可见性判断的候选版未解决用户复现的问题；不能把那些改动或隔离窗口实验当作已修复的证据。

## 最终修改

- 原生模块通过 AppKit `NSEvent.pressedMouseButtons` 获取当前鼠标按键。主进程以 16ms 周期发送光标与新鲜的按键采样时间，在跟随和独立桌面模式中均生效。
- 光标静止时仍发送按键证据，让底层应用中的释放能够解除 `externalDrag`；继续保留现有时间顺序检查，迟到的按下样本不能覆盖真实释放。
- macOS 关闭忽略窗口的鼠标移动转发，透明区域命中统一由原生采样驱动。挂件内的真实按下、释放和捕获逻辑保留。
- 原生可见性与层叠维护分别读取 AppKit 显示状态和真实窗口顺序，已正确排列时不重复调整，inactive Space 不强制重排。这些是辅助保护，不是此次锁死的直接原因。
- 状态接口补充输入与原生窗口布尔诊断。页面状态只接收 `held/externalDrag/hit/hidden` 四个布尔字段，不采集页面文字、设置值或凭证。

可见性保护参考了 [Electron 44.3.0 的 macOS 窗口实现](https://github.com/electron/electron/blob/v44.3.0/shell/browser/native_window_mac.mm)。Windows 的原生区域、按键采样来源及消息合并行为保持原有语义。

## 验证结果与范围

用户手动执行以下两项，回复“两种情况都正常了”：

1. 打开设置卡片，点击卡片和宠物之外，再点回卡片，重复数次。
2. 切换到其他桌面后返回，先点击 Codex，再点击宠物。

84 项相关单元回归通过，覆盖真实 `sendCursor` 函数、静止光标的释放消息、外部松开但没有 DOM pointerup 的场景、旧样本拒绝、捕获取消、位置交互、跟随层叠、可见性与 Windows 表面保护。原生模块通过 arm64/x86_64 编译，启用 `-Wall -Wextra -Werror`；包完整性及差异格式检查通过。没有声称多屏、睡眠唤醒或长期运行已验收。

完整测试运行：552 项，538 通过、6 失败、1 取消、7 跳过。失败/取消集中于既有测试夹具的 `AbortController`、`bubbleClickRevision`、`accountMode` 缺失、气泡配置转换及音频等待；在修改前 HEAD 的相同文件上单独复现了同一组问题。完整套件没有全绿，未把这些无关夹具问题并入本次修改。macOS IPC 测试使用短临时目录，避免系统默认临时目录超过 Unix socket 路径限制。

## 安装注意

本次已通过现有 Mac 安装器备份、编译原生组件并重启，保留用户设置和账本。向其他安装同步修复时须运行 `node scripts/install-macos.mjs`；只更新 JavaScript 或仅重启旧原生模块无法获得新按键采样接口。

手动验收由用户完成。诊断时读取了本地 IPC 和窗口元数据，没有自动替用户点击或切换桌面来宣称验收。
