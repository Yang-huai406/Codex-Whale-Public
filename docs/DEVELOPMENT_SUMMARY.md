# Level1 与本轮聊天内容摘要

本文汇总两页对话中与插件有关的目标、实现及最终决定，已去掉个人服务商、账号、本机路径、请求标识和原始日志，可供 README/GitHub 使用。历史对话中的中间方案不作为新指令；当前行为以本轮最终规则为准。

## Level1：从原框架到 Codex 适配

最初目标是将 dsh-whale-widget 0.3.0-beta 适配到 Codex，把特定服务余额查询改为当前 API 余额查询，并保留角色、动图、气泡编辑、音效、素材、拖动吸附、账本和提醒。

| 主题 | 形成的结果 |
| --- | --- |
| 产品形态 | 按需求移除独立网页、峰谷功能，使用透明窗口实现桌面挂件效果 |
| 自动启动 | 从易受终端关闭影响的监视器改为当前用户计划任务及 GUI 启动器 |
| 渲染 | 移除破坏画面的动态原生裁剪，采用内容缓冲、Alpha 命中缓存和观看期间快照 |
| 点击与动画 | 处理窗口遮挡和输入穿透，最终恢复 300 ms 翻转，而非保留早期取消插值的中间方案 |
| 金额显示 | USD/CNY 共用状态与格式化，余额、预警、预算统一换算和保留两位小数 |
| 跟随 | 使用 Windows 原生窗口事件，减少低频轮询导致的阶梯式移动 |
| 完成通知 | 区分主轮、子任务与继承历史；成功主轮去重，子任务保留用量 |
| 记账 | 保留跨午夜基线、待记账恢复日志和长期日汇总，处理延迟扣费与迟到子任务估算 |
| 素材与退出 | 验证图片/动画预算与格式，传播磁盘保存错误，回退损坏角色，限制退出等待 |
| 汇率 | 每日北京时间 00:15 检查、手动刷新，分别说明报价日期、检查时间和缓存 |
| 密钥边界 | 阻止项目更换域名后静默复用全局密钥，限制外链和本地通信 |

历史对话中的阶段测试数量、跟随延迟与启动耗时只属于当时结果，不作为本候选包的新性能承诺。所谓“多次结算”曾被核实为重复弹泡/响音，不能据此认定服务商重复扣款。

## 本轮：v0.2.0 修复与最终规则

本轮经只读分析、用户确认后写入，完成设置隐私、提示策略、汇率说明交互、窗口恢复及可分享打包。

1. API 设置不回显私有字段，未编辑保存不清空连接或价格。发布副本排除本机路径、运行数据与历史安装回执。
2. 汇率说明移至刷新右侧灰色圆形 `!`，按点击展开并支持键盘关闭。
3. 用可见性状态机和原生生命周期序号处理快速最小化漏采样、模态窗口、宿主变化；同时限制旧锚点越界。
4. 用户后续明确：取消不能用拥挤趣味文案，但运行到一半取消仍必须报消耗。因此最终采用中性费用结算，而不是将取消整体静默。
5. 只有指定 high demand 错误导致最终失败才显示“挤不进去...”；普通失败、重试和取消不能混为一类。
6. 基础版本统一为 0.2.0，提供通用安装、备份、回滚、隐私扫描和压缩包校验。

## 最终提示策略

| 最终状态 | 处理 |
| --- | --- |
| 成功 | 主轮按开关提示一次，成功音按用户设置播放 |
| 运行中取消 | 报告中性消耗，保留费用和 token，不播放成功音 |
| 取消时金额未确认 | 显示待记账/未知，不推断为免费 |
| 拥挤后取消 | 取消优先，不说“挤不进去...” |
| 取消后立即继续新轮 | 上一轮取消结算不因新轮开始而丢失 |
| 普通失败 | 独立趣味提示关闭，已观测用量保留在账本 |
| 明确拥挤导致最终失败 | 使用指定短句，抑制重试期间的过时提示 |

## 验证与交付边界

修复基线最终通过 170 项自动测试、14 项实际 UI 检查、100 次独立窗口最小化/还原和 50 次原生另存为打开/取消像素检查。失败尝试、测试通信异常和被其他窗口遮挡的轮次未计入通过结果。部分子任务曾因模型服务限制中断，其剩余工作由主任务接手完成，不代表修复仍有未交付项。

真实安装后，用户确认挂件重新显示；源码、安装目录、Codex 缓存和发布包曾逐文件核对一致。见 [验证记录](VALIDATION.md)。

之后用户明确授权将 v0.2(fixed) 上传到本项目 For-Codex 分支，并说明自己是协作者。上传前分支已有 0.2.4/macOS 成果；依用户确认，本次交付 Windows fixed 版本，既有成果保留在历史与归档供后续整合。只做普通分支提交，不修改仓库归属、不强推、不创建 tag 或 Release。

上传期间又收到“进程仍在，隐藏后再显示才能恢复”的实机反馈。本次补上显式显示和切回 Codex 的恢复路径，并在托盘增加恢复入口；没有把旧版自动测试结果视为穷尽所有实机问题。

用户之后进一步明确要求创建 Release 和 tag，因此增加 `v0.2.0-fixed` 的公开 Release；目标仍为 For-Codex，不替换主线 Latest，也不改仓库所有者。
