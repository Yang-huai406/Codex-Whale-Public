# macOS 紧凑挂件点击修复（本地验证版）

内部版本 `0.4.1`，构建标识沿用 `macos-space-binding-20261008`。

## 现象

macOS 跟随 Codex 时，挂件渲染在一个贴合鲸鱼的小原生窗口里。用户每点一下挂件，都会有一份同样的挂件图像在宿主左上角一闪而过。

## 成因

紧凑跟随器按渲染进程上报的 `dragging` 决定原生窗口尺寸：拖动时窗口扩成整个宿主矩形，其余时候只包住鲸鱼。宿主坐标系只在扩展后的窗口里才等于窗口坐标系。

- 旧实现只要 `pointerdown` 就加上 `dshwv-dragging`，于是**每次点击**都立刻扩展原生窗口。而小窗口的宿主偏移要等主进程回传新几何才更新，在这一两个 IPC 往返里渲染进程仍按旧偏移绘制，把鲸鱼画到宿主左上角。
- 原生窗口在静止光标下被移动时，macOS 会为同一个指针补发 `buttons: 0` 的移动事件。它也能把一次按压升级成拖动，从而在按住期间扩展窗口。

## 修复

- 位移超过点击阈值后才加 `dshwv-drag-moved`，紧凑跟随器改为只看这个状态；按下本身不再改变窗口尺寸。
- 鼠标指针没有按住主键时的移动事件直接忽略，不再参与拖动判定。

## 验证

- `node --test tests/position-interaction.test.mjs`：阈值内的抖动不请求扩展，无按键的移动不改变位置。
- `node tests/macos-compact-click.mjs`：隔离原生窗口加合成输入，不触碰 Codex 窗口和用户设置。12 次点击（按住 35／90／180 毫秒）全部不重定位原生窗口；真实拖动时原生窗口完成一次宿主切换，而挂件的宿主坐标在切换前后不跳变。

隔离夹具会丢弃混入的真实物理按键样本（那些样本属于第二个指针，不是产品缺陷），因此按有效样本数判定，并要求扩展阶段确实发生过一次窗口切换。

## 边界

未做 macOS 实机手感与多屏验证；Windows 路径不变。

## PR 拆分范围

本 PR 依赖 #18。紧凑尺寸代替主进程默认的一点宽度差方案，挂件位置保留在宿主坐标系，面板在原生窗口坐标系布局；真正拖动时才扩成宿主尺寸。原有历史验证记录针对本地整合版本，拆分分支另行验证。原生按键采样和极短点击动画分别由其他 PR 提供。
